# Offline Mandarin audio

The Android app plays bundled Ogg Vorbis recordings for characters and curated words. The pack is generated locally with the installed **Microsoft Huihui Desktop** Simplified Chinese voice and ffmpeg; the device needs no Chinese TTS engine for those clips and the app needs no Internet permission. No audio starts until a child taps a character or word.

From the project root, run `pwsh -NoProfile -File tools/audio-build.ps1` after updating `content/characters.json` or `content/words.json`. The script uses exact text from those files, creates only missing hash-named clips in `content/audio/clips`, and writes `content/audio/manifest.json` with paths and SHA-256 hashes. It never calls an online speech service. Keep the generated manifest and clips with the APK source. Existing clips are reused; to replace the voice or encoding, change the generator's versioned identity and regenerate the pack deliberately. On this development host, synthesis needed the unsandboxed user context; a voice shown in the installed list did not synthesize inside the restricted sandbox.

Run `pwsh -NoProfile -File tools/audio-validate.ps1` to check exact source coverage, clip hashes, and positive media duration with ffprobe. This checks the media files; it does not judge pronunciation quality.

Speech synthesis of an isolated Hanzi can choose a different reading for a polyphonic character. For example, the source card for `地` lists `de dì`; `发` can also change reading by meaning. The pack is synthetic Mandarin, not a verified pronunciation recording for every sense. Check those characters and words against the intended pinyin before presenting a specific reading as exact. A tapped word normally gives the speech engine more context than an isolated character.

If a requested clip is absent, `OfflineChineseSpeech` may use an Android TTS voice only when the engine lists a Chinese voice that does **not** require a network connection. If there is no such voice, the adapter reports the problem and exposes `voiceSetupIntent()` for a parent-only settings action. It does not start downloads or settings on its own. The `com.android.settings.TTS_SETTINGS` action is device-dependent; handle `ActivityNotFoundException` and offer the general device Settings screen if BOOX lacks it. After adding a voice, recreate the adapter or retry from a fresh activity instance. The Android 11+ manifest must declare a `<queries>` intent for `android.intent.action.TTS_SERVICE`; no Internet permission is needed.

Android references: [TextToSpeech initialization, stop, shutdown, and manifest query](https://developer.android.com/reference/android/speech/tts/TextToSpeech); [Voice network requirement](https://developer.android.com/reference/android/speech/tts/Voice); [engine service action](https://developer.android.com/reference/android/speech/tts/TextToSpeech.Engine). Device-specific settings actions are not guaranteed by those APIs.
